Inspector information architecture / decision
Requested direction

Make Feedback the work surface. Make History the record.

Accept and Reopen belong beside the comments they govern—not behind a separate Verify tab. The remaining choice is how History should organize past comments and amendments once they are no longer the reviewer’s immediate task.

Review protocol The two-tab direction is carried forward: Feedback contains drafts and every Accept/Reopen review item; History is read-only. Compare the two History specimens below. Approve to select the recommended revision-cycle ledger, or annotate a specimen and choose Revise using feedback.
Settled versus open

One UX decision remains.

This review does not reconsider whether review items move into Feedback or whether Verify becomes History. It decides only how the new read-only history is grouped.

Settled direction

Feedback owns every current action.

Private drafts, Additional feedback, addressed items, accepted items, Accept, and Reopen share one scrollable surface. Accepted items retain their evidence but no longer highlight the artifact.

Recommendation

Choose the revision-cycle ledger.

Blueprint’s artifact lifecycle is revision-first. Grouping the record the same way makes every amendment traceable to the feedback batch that caused it and keeps “what changed together?” easy to answer.

History modelBest atCostPersistence impact
Revision-cycle ledgerReconstructing each review round and its evidenceA long-lived issue spans multiple groupsRead existing immutable packets and reports through a lazy reviewer-only history projection
Comment-thread ledgerFollowing one concern across repeated reopen cyclesObscures the sequence and context of each delivered revisionSame records, but more client-side cross-linking and repeated revision context
Implementation boundary

One action surface, one read-only record.

The recommendation adds no second editing path and does not change the immutable packet/report formats. History is fetched only when opened so normal review state stays compact.

01

Write in Feedback

Draft comments stay private and editable beside current review items.

02

Request revision

Revise using feedback sends the current draft batch through the existing packet contract.

03

Review in Feedback

Before/after evidence and Accept/Reopen appear in the main work surface.

04

Read in History

Past comment and amendment cycles remain inspectable but never become another action queue.

Authority boundary Approving this review authorizes local implementation of the combined Feedback surface, the renamed History tab, the recommended revision-cycle history projection, tests, and durable documentation. It does not authorize external publishing, package release, or unrelated protocol expansion.
