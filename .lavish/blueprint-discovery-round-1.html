Design direction, not implementation

What round two would establish

After these choices, the next review can focus entirely on the chosen inspector states, packet composer, and verification experience.

Proposed Blueprint experience constitution

  • The agent never steals focus and never changes a visible review without a human reveal action.
  • Visual and interaction choices are shown as actual propositions, including motion when motion is part of the choice.
  • Feedback remains private and editable until the reviewer queues and explicitly sends one packet.
  • Connection and revision state is durable, named precisely, and recoverable without losing work.
  • Review content is compact first; evidence and technical depth remain available on demand.

Ground-up guardrail

A new architecture should not mean relearning old failures. We will write fresh product contracts and tests for sandboxing, acknowledged delivery, durable drafts, revisions, and export before selecting implementation components. Any copied MIT code will retain its required notices.

No implementation is authorized by this review. Make local selections, use each section’s Queue response control, then use Lavish’s existing Send to Agent or Send & End action. The next round will replace resolved questions with working interaction prototypes rather than adding another long requirements page.
